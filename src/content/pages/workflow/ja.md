AI エージェント（Claude Code）を開発チームのように使い、自分は設計・判断・レビューに集中しています。コードを書くのが AI でも、仕様と品質に責任を持つのは自分です。

## プロジェクトの始め方

- まずは AI と会話し、何を作りたいのかをしっかり伝えます
- 頭の中にあるアーキテクチャやデータベースの構造まで、プロジェクトの全体像を伝えます
- AI が正しく理解できたところで開発を始め、最初に `CLAUDE.md` を用意します。構成・ルール・落とし穴をまとめた「生きたドキュメント」で、エージェントは毎回ここから読み始めます

## 進め方：仕様 → 計画 → 実装

1. **仕様書** — 決めた内容を AI が Markdown の仕様書にまとめ、自分がレビューする
2. **実装計画** — 仕様を小さなタスクに分解する
3. **計画どおりに実装** — タスクごとにサブエージェントが担当し、テスト駆動（TDD）で進める
4. **レビュー** — タスクごと、そして最後にブランチ全体を別のエージェントがレビューする

この流れは、Claude Code のプラグイン **Superpowers** で回しています。

## エージェント

担当分野ごとにサブエージェントを用意しています。

- **バックエンド** — Go、API
- **フロントエンド** — React、TypeScript
- **データベース** — スキーマ、マイグレーション、クエリ
- **コードレビュー**

大きなタスクは分割してサブエージェントに任せます。それぞれが自分の文脈だけで作業できるので、開発がシンプルで速くなります。

## 技術スタック

いま基本としているのは次の組み合わせです。

- **バックエンド** — Go ＋ Gin
- **DB アクセス** — sqlc（SQL から型安全な Go のコードを生成）
- **データベース** — PostgreSQL
- **フロントエンド** — React ＋ TypeScript
- **インフラ** — すべて Docker で動かし、Traefik をリバースプロキシとして前段に置く

これはあくまで土台で、プロジェクトに応じて必要なライブラリを選んで使います。

<p class="note">※ 例えば、このポートフォリオサイトは静的なページと 3D モデルが中心なので、React より軽い <b>Astro</b> で作りました。</p>

## ツール：MCP とプラグイン

Claude Code には、次の MCP サーバーとプラグインを入れています。

- **Serena** — シンボル単位でのコード検索・ナビゲーション
- **Context7** — ライブラリの最新ドキュメント
- **GitHub** — Issue、プルリクエスト、レビュー
- **Figma** — デザインとコードの行き来
- **Notion** — メモとドキュメント
- **Claude in Chrome** — 実際のブラウザでの動作確認
- **プラグイン** — Superpowers（開発プロセス）、frontend-design、code-review

このサイトも同じ流れで作りました。
